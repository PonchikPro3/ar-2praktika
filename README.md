# WebAR — управление моделями

Простое приложение на Three.js по [официальному примеру hit-test](https://github.com/mrdoob/three.js/blob/dev/examples/webxr_ar_hittest.html).

**Открыть на телефоне:** https://ponchikpro3.github.io/ar-2praktika/

1. Используйте Chrome на Android с поддержкой WebXR AR / ARCore.
2. Нажмите «Запустить AR» и разрешите камеру.
3. Направьте телефон на пол или стол и дождитесь кольца.
4. Коснитесь экрана или нажмите «Разместить модель». Она останется на поверхности при движении камеры.
5. Выберите **Babuleh Cat**, **Sunny Kitty** или **Macdonald** в списке. Кнопки **−15° / +15°** поворачивают модель. При переключении сохраняются точка размещения и угол поворота; можно выбрать модель и до размещения.
6. «Разместить заново» возвращает поиск поверхности; «Выйти из AR» завершает сессию.

Панель работает через WebXR DOM overlay, который запрашивается как обязательная возможность. Кнопки, список, подписи и свободные участки панели отменяют `beforexrselect`: управление не вызывает случайное размещение. Остальной экран принимает тапы для размещения. На низком/горизонтальном экране панель прокручивается; учитываются безопасные отступы телефона.

## Модули

- `index.html`, `style.css` — интерфейс, import map и мобильная AR-панель.
- `src/app.js` — создание сцены и соединение модулей.
- `src/models.js` — `ModelManager`: GLTFLoader, кеш, смена и поворот. Устаревшие результаты быстрого переключения игнорируются. Ошибка загрузки сохраняет предыдущую модель и позволяет повторить выбор.
- `src/model-utils.js` — нормализация размеров и PBR-материалы.
- `src/lighting.js` — загрузка HDRI через HDRLoader и подготовка environment map через PMREMGenerator.
- `src/ar.js` — `ARPlacement`: сессия, hit-test, фиксация, сброс и выход.
- `src/ui.js`, `src/events.js` — состояние интерфейса и обработчики событий.
- `src/placement.js` — однократное копирование мировой позы маркера.
- `assets/` — три GLB и `lightroom_14b.hdr`. Длиннейшая сторона каждой модели нормализуется до 30 см; низ совпадает с поверхностью. HDRI скопирована из существующих локальных ресурсов. Проект `ar-shield` не изменяется.
- `vendor/` — Three.js 0.180.0, GLTFLoader, HDRLoader, BufferGeometryUtils и MIT-лицензия. Импорты локальные, одной версии; CDN при запуске не нужен.

## Освещение и размещение

Исходные GLB содержат `KHR_materials_unlit`. При загрузке `MeshBasicMaterial` заменяется на **MeshStandardMaterial** с сохранением цветовой текстуры, цвета, прозрачности и стороны материала: `roughness = 0.8`, `metalness = 0`. Уже имеющиеся PBR-материалы сохраняются. HDRI превращается в environment map и назначается `scene.environment`; `scene.background` остаётся пустым для реальной камеры.

Сессия запрашивается через `navigator.xr.requestSession('immersive-ar', ...)` с обязательными `hit-test`, `local-floor` и `dom-overlay`. Источник hit-test использует `viewer`; `getHitTestResults()` и `getPose(renderer.xr.getReferenceSpace())` дают позу в том же `local-floor`, в котором работает рендерер. Кольцо показывает горизонтальную поверхность. DOM-кнопка размещения обрабатывается в активном XR-кадре.

Нормализация, пользовательский поворот и мировая поза находятся в отдельных вложенных группах. Модель добавлена в сцену независимо от камеры и маркера; после размещения поза больше не обновляется. При выходе источник отменяется, модель скрывается. Размещение действует в текущей сессии, без постоянного XRAnchor.

## Запуск и проверки

```sh
npm start
# http://localhost:8080
npm ci
npm test
npx playwright install chromium
npm run test:browser
```

Для установленного Edge на Windows: `$env:PLAYWRIGHT_CHANNEL = 'msedge'`, затем `npm run test:browser`.

Для AR на телефоне нужен HTTPS. GitHub Pages публикует `main` / корень репозитория; относительные пути работают в `/ar-2praktika/`.

Проверяются PBR-преобразование с сохранением текстуры, нормализация, независимость мировой позы от камеры, загрузка настоящих GLB/HDRI и импортов, мобильный интерфейс, отказ в разрешении, размещение/сброс/повторный запуск, поворот, смена трёх моделей с сохранением мировой позы, быстрое переключение, восстановление после ошибки загрузки и блокировка `beforexrselect` на UI. AR-тест использует mock WebXR с настоящим Three.js WebXRManager. Физическую камеру и точность трекинга необходимо проверить на реальном совместимом Android; устройство к среде разработки не подключено.
