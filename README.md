# WebAR — babuleh cat

Простое приложение на Three.js по [официальному примеру hit-test](https://github.com/mrdoob/three.js/blob/dev/examples/webxr_ar_hittest.html).

**Открыть на телефоне:** https://ponchikpro3.github.io/ar-2praktika/

1. Используйте Chrome на Android с поддержкой WebXR AR / ARCore.
2. Нажмите «Запустить AR» и разрешите камеру.
3. Направьте телефон на пол или стол и дождитесь кольца.
4. Коснитесь экрана или нажмите «Поставить кота». Модель останется на поверхности при движении камеры.
5. «Разместить заново» возвращает поиск поверхности; «Выйти из AR» завершает сессию. Без DOM overlay используйте системную кнопку выхода.

## Код

- `index.html` — минимальный интерфейс и import map.
- `src/app.js` — загрузка GLB, сцена, сессия и hit-test.
- `src/placement.js` — однократное копирование позы маркера в модель.
- `assets/babuleh_cat.glb` — модель кота. Длиннейшая сторона нормализуется до 30 см; низ модели совпадает с поверхностью.
- `vendor/` — Three.js 0.180.0, GLTFLoader, его BufferGeometryUtils и MIT-лицензия. Все импорты локальные, одной версии; CDN при запуске не нужен.

Сессия запрашивается через `navigator.xr.requestSession('immersive-ar', ...)` с обязательными `hit-test` и `local-floor`. Источник hit-test использует `viewer`; `getHitTestResults()` и `getPose(renderer.xr.getReferenceSpace())` дают позу в том же `local-floor`, в котором работает рендерер. Кольцо показывает горизонтальную поверхность. Модель добавлена в сцену отдельно от камеры и маркера; после размещения её поза не обновляется. Кнопка размещения обрабатывается в активном XR-кадре. При выходе источник отменяется, модель скрывается.

## Локальный запуск и тесты

```sh
npm start
# http://localhost:8080
npm ci
npm test
npx playwright install chromium
npm run test:browser
```

Для установленного Edge на Windows: `$env:PLAYWRIGHT_CHANNEL = 'msedge'`, затем `npm run test:browser`.

Для AR на телефоне нужен HTTPS. GitHub Pages публикует `main` / корень репозитория; все пути относительные и работают в `/ar-2praktika/`.

Проверяются загрузка настоящей GLB и импортов, мобильный экран, отказ в разрешении, размещение/сброс/повторный запуск через mock WebXR с настоящим Three.js WebXRManager, а также независимость мировой позы от движения камеры. Физическая камера и точность трекинга требуют проверки на реальном совместимом Android; устройство к среде разработки не подключено. Размещение действует в текущей сессии, без постоянного XRAnchor.
