# WebAR с размещением куба через hit-test

Задание 4: Three.js + WebXR API, сессия `immersive-ar`, поиск поверхности и размещение куба размером 20 × 20 × 20 см.

**Страница:** https://ponchikpro3.github.io/ar-2praktika/

## Как использовать

1. Откройте страницу в Chrome на Android с поддержкой WebXR AR / ARCore.
2. Нажмите **«Запустить AR»**, разрешите использование камеры.
3. Плавно перемещайте телефон, направляя камеру на хорошо освещённый пол или стол с различимой текстурой.
4. Дождитесь мятного кольца и коснитесь экрана. При наличии DOM overlay можно нажать **«Разместить куб»**.
5. Обойдите объект: он остаётся в месте размещения. Следующие тапы его не перемещают.
6. **«Разместить заново»** удаляет куб и снова включает поиск. **«Выйти»** завершает сессию. Если браузер не предоставляет DOM overlay, используйте системный выход из AR.

Это простое полноэкранное приложение: кнопка запуска, инструкция, AR-сцена и кнопки размещения/сброса/выхода. При отсутствии WebXR кнопка AR отключена с пояснением. Для работы на телефоне необходимы Chrome на Android и устройство с поддержкой WebXR AR / ARCore; сама камера без поддержки WebXR не позволяет выполнить hit-test.

## Реализация

- `navigator.xr.requestSession('immersive-ar', ...)` вызывается из обработчика нажатия. `hit-test` и `local-floor` входят в `requiredFeatures`, `dom-overlay` — в `optionalFeatures`.
- `renderer.xr.setReferenceSpaceType('local-floor')` вызывается до начала сессии. `local-floor` — тип пространства координат, а `immersive-ar` — режим сессии.
- Источник `XRHitTestSource` создаётся через `session.requestHitTestSource({ space: viewerSpace })`, где `viewerSpace` получено из `requestReferenceSpace('viewer')`. Луч направлен вперёд от камеры.
- В XR-кадре `frame.getHitTestResults(hitTestSource)` возвращает пересечения. Их позы получаются через `hit.getPose(renderer.xr.getReferenceSpace())`: это то же `local-floor`, в котором Three.js рисует сцену.
- Отбираются поверхности с нормалью вверх (отклонение от горизонтали до ~32°). Кольцо обновляется только по текущей валидной позе и скрывается при потере попадания/трекинга.
- При XR-событии `select` поза обновляется из `event.frame`, затем матрица маркера **один раз копируется** в позицию и ориентацию отдельной группы куба. Группа добавлена непосредственно в `scene`, а не в камеру, контроллер или маркер. Геометрия поднята на 0,1 м, чтобы её низ совпадал с плоскостью.
- Нажатие DOM-кнопки размещения обрабатывается в следующем активном XR-кадре, поскольку вызовы позы вне активного XRFrame запрещены WebXR. Тап в AR использует активный `event.frame` события `select`.
- После размещения координаты объекта больше не обновляются. При завершении сессии источник отменяется (`cancel()`), объект и маркер скрываются, экран запуска восстанавливается. Новая сессия создаёт новый источник.
- Фиксация действует в пределах текущей сессии. Это размещение в мировых координатах `local-floor`, без постоянного XRAnchor и без сохранения между перезапусками; точность зависит от трекинга устройства.

Основа — [официальный пример Three.js webxr_ar_hittest](https://threejs.org/examples/webxr_ar_hittest.html); настройки сессии: [WebXR requestSession](https://developer.mozilla.org/en-US/docs/Web/API/XRSystem/requestSession).

## Запуск и проверки

Страница статическая, сборка и серверные зависимости не требуются. Three.js **0.180.0** сохранён в `vendor/` вместе с MIT-лицензией; загрузка с внешнего CDN при открытии страницы не нужна.

Для локального предпросмотра нужен Node.js:

```sh
npm start
# http://localhost:8080
```

На телефоне используйте HTTPS-ссылку GitHub Pages: обычный HTTP по LAN-IP не является безопасным контекстом WebXR.

```sh
npm ci
npm test
npx playwright install chromium
npm run test:browser
```

Для установленного Microsoft Edge на Windows можно вместо скачивания Chromium:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:browser
```

Автоматические проверки: независимость мировой матрицы объекта от движения камеры/маркера; экран запуска на телефоне без прокрутки; отказ в разрешении и повторный запуск; XRSession с обязательным `local-floor`, источник в `viewer`, поза в пространстве рендера; запрет размещения без попадания и на стене; размещение тапом и кнопкой только в активном XRFrame; потеря трекинга; сброс и очистка при выходе. Браузерный AR-тест использует детерминированный mock WebXR API с настоящим Three.js WebXRManager — он не подтверждает качество трекинга реального устройства.

### Проверка на устройстве / эмуляторе

Реальное Android-устройство не подключено к среде разработки, поэтому физический трекинг и камера здесь не проверены. На телефоне пройдите шаги выше, после размещения сместитесь на 1–2 м, поверните камеру, проверьте, что куб остался на поверхности; затем проверьте повторное размещение, выход и повторный запуск.

В WebXR Emulator / совместимом XR-эмуляторе выберите AR-устройство с `immersive-ar`, `hit-test` и `local-floor`, задайте плоскость, дождитесь кольца, вызовите `select`, затем измените положение камеры. Если расширение не предоставляет hit-test, используйте реальное устройство.

## GitHub Pages

Публикация: **Settings → Pages → Deploy from a branch → main → /(root)**. После push в `main` GitHub Pages обновляет сайт автоматически. `.nojekyll` отключает ненужную обработку Jekyll. Все пути относительные, поэтому страница работает в подпапке `/ar-2praktika/`.

## Файлы

- `index.html`, `style.css` — адаптивный интерфейс и AR overlay.
- `src/app.js` — сцена, WebXR, hit-test и обработка сессий.
- `src/placement.js` — фиксация мировой позы.
- `vendor/` — Three.js и лицензия.
- `tests/` — тест мировой позы и браузерные проверки.
- `scripts/serve.js` — локальный сервер предпросмотра.
